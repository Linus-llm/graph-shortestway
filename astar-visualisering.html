How to run and interpret this visualization

Run Astar.main, then select the generated astar-trace.json. The console prints its full path. After a Java change, run main again and select the new file. Previous and Restart replay the same recording.

The recorder polls a copy of the real PriorityQueue and reads g and f from CityNodeWithDistA. It does not modify the original queue, dist, prev or visited. Grey appears at your visited.add call. The goal check happens before that call, so the goal need not enter visited. Green follows the final prev chain. Duplicate and stale queue entries are preserved.

Your grid uses four-direction moves with weight 1 and a Manhattan heuristic. Walls can force detours, so h can be lower than the actual distance remaining. The final route cost is the sum of edge weights (g), not f values along the path.
